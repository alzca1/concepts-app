# Deploy to GitHub Pages — Step by Step

This guide explains how to automatically deploy the app to GitHub Pages using a GitHub Actions workflow.

---

## 1. How it works

The workflow (`.github/workflows/deploy.yml`) runs on every push to `main` and consists of two jobs:

1. **Build** — installs dependencies, runs `npm run build`, and uploads the `dist/` folder as a Pages artifact.
2. **Deploy** — takes that artifact and publishes it to GitHub Pages.

---

## 2. Steps to enable GitHub Pages

### 2.1 Enable Pages in the repository settings

1. Go to **Settings → Pages** (or `https://github.com/<owner>/<repo>/settings/pages`).
2. Under **Build and deployment**, select:
   - **Source**: GitHub Actions
3. Click **Save**.

> No branch selection needed since the workflow controls the deployment.

### 2.2 Merge the workflow

The workflow file is already committed in this branch (`internal/INT-006-react-router`). Once merged into `main`, every push to `main` will trigger the deploy.

### 2.3 Verify the deployment

After merging:

1. Go to the **Actions** tab in the repository.
2. You should see a "Deploy to GitHub Pages" workflow run in progress.
3. Once it finishes, the app will be live at:
   ```
   https://<owner>.github.io/<repo>/
   ```

---

## 3. How the workflow is triggered

| Trigger | Result |
|---|---|
| Push to `main` | Automatic deploy |
| Manual trigger ("workflow_dispatch") | Go to Actions → workflow → Run workflow |

---

## 4. Custom domain (optional)

If you want to use a custom domain (e.g. `concepts.app`):

1. In **Settings → Pages**, enter your domain under **Custom domain**.
2. Add a `CNAME` file to the `public/` folder (Vite copies it to `dist/` on build):
   ```
   concepts.app
   ```
3. GitHub will automatically provision an SSL certificate.

## 5. Environment variables (Supabase)

The build needs `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`
at compile time. Vite reads them from `import.meta.env`, which is
populated from process env or `.env.local` (gitignored).

### 5.1 Local development

Copy `.env.example` to `.env.local` and fill the values from your
Supabase project: **Settings → API**.

```
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

### 5.2 Production (GitHub Pages)

The workflow does **not** read env vars from the repo (we don't
want credentials in git). Configure them as repository secrets:

1. **Settings → Secrets and variables → Actions**.
2. **New repository secret** for each:
   - `VITE_SUPABASE_URL` — Project URL.
   - `VITE_SUPABASE_ANON_KEY` — `anon public` key.
3. The build job passes them to Vite with the `env:` block. Add
   these two lines to `.github/workflows/deploy.yml` under the
   `Build` job's `Build` step:

   ```yaml
   - name: Build
     run: npm run build
     env:
       VITE_SUPABASE_URL: ${{ secrets.VITE_SUPABASE_URL }}
       VITE_SUPABASE_ANON_KEY: ${{ secrets.VITE_SUPABASE_ANON_KEY }}
   ```

> The `anon public` key is meant to be public (it ships in the
> bundle). Security relies on Row-Level Security, not on keeping
> the key secret. Do **not** expose the `service_role` key.

## 6. Repository structure reference

```
.github/
  workflows/
    deploy.yml       ← the workflow
public/
  (static assets)
src/
  (React app)
supabase/
  schema.sql        ← run once in the Supabase SQL editor
  README.md
.env.local          ← gitignored, holds Supabase credentials
.env.example        ← documented template
dist/               ← generated by `npm run build`, NOT committed
```
