= My cards

The `/cards` page shows the whole deck: the mode switcher, stats bar,
search and tag filters, and a responsive card grid (2 columns on
mobile, 3 from 700 px and 4 from 1200 px).

== Mode switcher

The «Mis tarjetas / Estudiar» switcher lives **inside the page**, not
in the header: it is the shared `ModeTabs` component
(`common/components/domain/mode-tabs/`), a `<nav class="mode-tabs">`
that links to `/cards` and `/study` and marks the active one. The
header only carries the language selector and the user menu.

`ModeTabs` is rendered by the cards page *and* by the study page (in
its session, summary and empty states), so the switcher is always
reachable — see xref:study-mode.adoc[study mode].

== Card grid

* Cards flip **only by click** (or keyboard: `Enter` / space); there
  is no hover flip.
* Flipping is **controlled by the grid**: a single `flippedId` lives
  in `ConceptList`, so flipping a card resets the previous one and
  *only one answer is visible at a time*.
* Edit (✎) and delete (✕) icons live **inside the front face**
  (`actions` prop of `FlashCard`), so they rotate together with the
  card; while the card faces away they are `visibility: hidden` and
  out of the tab order.
* Deleting asks for confirmation (`window.confirm`) and mentions the
  card title.
* The fixed face heights (190 px grid, 300 px study) are preserved
  even with long content — see xref:flash-card.adoc[flash card].

== Add card

There is no separate «new card» button: the action is a **dashed
placeholder card** (`AddCard`) that always occupies the **first cell
of the grid**, even when the deck is empty or filtered out.

It mimics the look of a regular card (same padding, radius and
translucent background) but with a dashed border, and it shows:

* the tag chip replaced by the word «Tópico»,
* the title «Añade una nueva tarjeta»,
* the hint «Clic para crear nueva tarjeta».

It is a real `<button>`, so it is reachable with the keyboard and
exposes an accessible name.

== Search and filters

* **Search** matches `front`, `back` and `tag`, case-insensitive and
  `trim`-normalized.
* **Tag filter chips** get a stable color per tag (`tagColor`); the
  first chip, «Todos», clears the filter and is active whenever no
  tag is selected. Clicking the active chip also clears it. All
  chips expose `aria-pressed`.
* **Empty state**: distinct messages for "no results with active
  filters" vs. "deck is actually empty". It is shown above the grid,
  which always renders (at least the add card).

== Stats bar

Shows the number of cards and the number of distinct tags. New
users start with an empty deck — see R6.4.

== Loading and error states

`useConcepts` fetches the cards from Supabase on mount and whenever
the session changes. While the request is in flight the page shows
the `home.loading` message; if the request fails, `home.loadError`
includes the underlying error message and is announced with
`role="alert"`.
